# Учебный сайт на Laravel

Учебный проект по серверной веб-разработке. В лабораторной работе № 6 реализованы регистрация и аутентификация пользователей, работа с сессиями и Sanctum-токенами, защита маршрутов middleware `auth:sanctum` и выход с аннулированием сессии и обновлением CSRF-токена.

## Реализовано

- Регистрация нового пользователя через Blade-форму.
- Валидация данных регистрации:
  - обязательное имя с максимальной длиной 255 символов;
  - обязательный уникальный корректный email;
  - обязательный пароль длиной не менее 8 символов.
- Сохранение пользователя в таблице `users` с хешированием пароля.
- Redirect после регистрации на форму авторизации.
- Форма входа с email и паролем.
- Аутентификация пользователя с использованием сессионного guard Laravel.
- Обновление идентификатора сессии после успешного входа.
- Защита от частых попыток входа с помощью middleware ограничения запросов.
- Выход пользователя с удалением аутентификации.
- Аннулирование сессии и обновление CSRF-токена при выходе.
- Redirect после входа и выхода на главную страницу.
- Middleware `auth:sanctum` для маршрутов, доступных только авторизованным пользователям.
- Добавление и настройка пакета Laravel Sanctum.
- Blade-навигация с разными элементами для гостей и авторизованных пользователей.
- Заметка об успешной регистрации и сообщения об ошибках валидации и неверных учетных данных.
- Полный CRUD для новостей с пагинацией и валидацией через `ArticleRequest`.
- CSRF-защита всех state-changing форм.

## Регистрация

Регистрация реализована в `App\Http\Controllers\AuthController`.

Методы контроллера:

- `create` — отображение Blade-формы регистрации;
- `store` — валидация и сохранение нового пользователя.

Для валидации используются массивы правил Laravel и явные сообщения об ошибках. Email проверяется на уникальность в таблице `users`.

Форма регистрации содержит `@csrf` и отправляет данные методом `POST`. После успешной регистрации пользователь перенаправляется на форму входа.

## Авторизация

Форма входа реализована Blade-шаблоном `resources/views/auth/login.blade.php`.

Методы контроллера:

- `showLoginForm` — отображение формы входа;
- `login` — проверка email и пароля;
- `logout` — завершение авторизованной сессии.

При успешной аутентификации используется стандартный guard `web`, идентификатор сессии обновляется методом `regenerate()`, а пользователь перенаправляется на главную страницу.

При ошибке входа форма возвращает сообщение `Неверный email или пароль.` и сохраняет введенный email.

Маршрут входа ограничен middleware ограничения запросов:

```php
Route::post('/login', [AuthController::class, 'login'])
    ->middleware('throttle:6,1');
```

## Выход

При выходе выполняются следующие действия:

- вызывается `Auth::guard('web')->logout()`;
- выполняется `$request->session()->invalidate()` для аннулирования сессии;
- выполняется `$request->session()->regenerateToken()` для обновления CSRF-токена;
- пользователь перенаправляется на главную страницу.

Выход доступен только авторизованному пользователю и защищен middleware `auth:sanctum`.

## Защита маршрутов Sanctum

Маршруты новостей, галереи и выхода объединены в одну защищенную группу:

```php
Route::middleware('auth:sanctum')->group(function () {
    Route::post('/logout', [AuthController::class, 'logout'])->name('logout');
    Route::resource('articles', ArticleController::class);
    Route::get('/galery/{article}', [MainController::class, 'galery'])
        ->whereNumber('article')
        ->name('galery');
});
```

Маршруты регистрации и входа объединены в группу `guest`, поэтому авторизованный пользователь не должен повторно открывать формы аутентификации.

## Модель и таблица пользователей

Модель `App\Models\User` наследует `Illuminate\Foundation\Auth\User` и использует Laravel Sanctum вместе со стандартной сессионной аутентификацией.

Таблица `users` содержит:

- `name` — имя пользователя;
- `email` — уникальный адрес электронной почты;
- `email_verified_at` — необязательная дата подтверждения email;
- `password` — хешированный пароль;
- `remember_token` — токен для функции запоминания пользователя;
- `created_at` и `updated_at` — даты создания и изменения записи.

Пароль автоматически хешируется через cast модели:

```php
'password' => 'hashed',
```

## Новости и CRUD

Для работы со статьями используется resource-контроллер `ArticleController`. Он реализует методы:

- `index` — получение списка новостей с пагинацией;
- `create` — отображение формы создания;
- `store` — проверка и сохранение новой новости;
- `show` — отображение выбранной новости;
- `edit` — отображение формы редактирования;
- `update` — проверка и обновление новости;
- `destroy` — удаление новости.

Маршруты оформлены с помощью `Route::resource('articles', ArticleController::class)`. Для передачи идентификатора новости используется неявная привязка модели Eloquent.

Модель `App\Models\Article` связана с таблицей `articles`:

- `title` — заголовок новости;
- `content` — текст новости;
- `published_at` — дата публикации;
- `created_at` и `updated_at` — даты создания и изменения записи.

Проверка данных статей выполняется в `App\Http\Requests\ArticleRequest`.

Правила валидации:

- `title` — обязательное текстовое поле, максимум 255 символов;
- `content` — обязательное текстовое поле;
- `published_at` — необязательное корректное значение даты.

## Запуск проекта

Требуются PHP 8.3 или новее и Composer.

```bash
composer install
```

Создайте файл `.env` на основе `.env.example`, настройте подключение к базе данных и сгенерируйте ключ приложения:

```bash
php artisan key:generate
```

Примените миграции и заполните базу тестовыми данными:

```bash
php artisan migrate --seed
```

Запустите локальный сервер:

```bash
php artisan serve
```

Откройте адрес, указанный Artisan (обычно `http://127.0.0.1:8000`).

Для повторного создания таблиц и наполнения базы данными:

```bash
php artisan migrate:fresh --seed
```

> `migrate:fresh` удаляет все существующие таблицы в выбранной базе данных. Используйте эту команду только для локальной или тестовой базы.

## Тестирование

Запустите тесты проекта:

```bash
php artisan test
```

Feature-тесты проверяют регистрацию, уникальность email, хеширование пароля, вход, неверные учетные данные, выход, аннулирование сессии, защиту CSRF и доступ неавторизованных пользователей к закрытым маршрутам.

Отдельные тесты контроллеров проверяют CRUD новостей, пагинацию, Blade-формы, валидацию и корректность сохранения данных.

## Краткое описание для отчёта

В лабораторной работе № 6 реализованы регистрация и авторизация пользователей в Laravel-приложении. Пользователь может создать учетную запись, войти по email и паролю и выйти из системы. Данные регистрации проходят предварительную валидацию, уникальность email проверяется в базе данных, а пароль сохраняется в хешированном виде.

Для входа используется сессионная аутентификация Laravel с Sanctum. После успешного входа сессия обновляется, а после выхода аннулируется и обновляется CSRF-токен. Маршруты новостей и галереи защищены middleware `auth:sanctum`, поэтому неавторизованные пользователи перенаправляются на страницу входа.

Сохранена функциональность предыдущей лабораторной работы: пагинация новостей и полный CRUD статей с Blade-формами, CSRF-токенами и валидацией данных через `ArticleRequest`.
